# 合作方上手指南

## 10 分钟接入

1. 进入 `SEO自动检查门禁`。
2. 进入工具包目录运行：

```bash
pnpm install
```

3. 复制示例配置：

```bash
cp examples/seo-gate.config.json seo-gate.config.json
```

4. 修改 `seo-gate.config.json`：
   - `site.publicBaseUrl`：线上 canonical 域名。
   - `site.localBaseUrl`：本地或预发服务地址。
   - `localVerify.commandCwd`：目标项目的工作目录。
   - `localVerify.buildCommand`：生产构建命令。
   - `localVerify.startCommand`：生产服务启动命令。
   - `localVerify.requiredPages`：上线前必须检查的代表页。
   - `sitemaps.childSitemaps`：你的子 sitemap 文件。
   - `sitemaps.deepAudit`：`sample` 或 `all`，控制 sitemap HTML 深度审计范围。
   - `cache`：缓存目录、TTL、是否缓存失败结果。
   - `links`：内链、出站链接、UGC、sponsored、noopener 检查规则。
   - `specialPages`：404、noindex、legacy redirect 页面。
   - `indexNow`：IndexNow key 和默认提交 sitemap。

5. 运行本地门禁：

```bash
pnpm run seo:verify -- --config seo-gate.config.json
```

6. 部署后运行线上审计：

```bash
pnpm run seo:audit -- --config seo-gate.config.json
```

7. 大版本发版或月度巡检时重抓并预热缓存：

```bash
pnpm run seo:audit:fresh -- --config seo-gate.config.json
```

## 推荐 CI 接入

```yaml
name: SEO Gate

on:
  pull_request:
  push:

jobs:
  seo:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: pnpm/action-setup@v4
        with:
          version: 10
      - uses: actions/setup-node@v4
        with:
          node-version: 20
      - run: pnpm install
        working-directory: SEO自动检查门禁
      - run: pnpm run seo:verify -- --config seo-gate.config.json
        working-directory: SEO自动检查门禁
```

## 配置说明

- `pageRules.titleMinLength`：标题最小长度，默认建议 10。
- `pageRules.descriptionMinLength`：描述最小长度，默认建议 40。
- `pageRules.requiredHreflangCount`：多语言站建议至少 3，即两个语言 + `x-default`。
- `pageRules.requireViewport`：要求页面包含 viewport。
- `pageRules.checkOgImageAccessible`：检查 OG 图片是否 200 且为图片类型。
- `pageRules.schemaRules`：按路径匹配 schema 类型，例如 `/blog/` 对应 `BlogPosting`。
- `sitemaps.forbiddenUrlPatterns`：禁止进入 sitemap 的 URL 正则，例如 `/result`、小写类型页、带参数页。
- `sitemaps.deepAudit`：`all` 会检查每个 sitemap URL 的 canonical、noindex、head、JSON-LD、OG 图。
- `cache.ttlHours`：无 lastmod/etag 时的缓存有效期。
- `links.requireNoopenerForBlank`：`target="_blank"` 外链必须带 `rel="noopener"`。
- `links.sponsoredPatterns`：命中的商业/赞助外链必须带 `rel="sponsored"`。
- `links.ugcSelectors`：指定区域内的外链必须带 `rel="ugc"` 或 `nofollow`。
- `specialPages.noindexPages`：结果页、搜索页、隐私性页面等不应收录的页面。
- `specialPages.legacyRedirects`：历史 URL，必须跳转但不能进入 sitemap 或主内链。

## 失败排查

- `canonical mismatch`：页面 canonical 没有指向 `site.publicBaseUrl + path`。
- `missing hreflang`：页面缺少语言替代链接，或数量低于配置。
- `missing JSON-LD`：页面没有结构化数据，或 schema 类型与配置不匹配。
- `JSON-LD block is not valid JSON`：结构化数据无法解析。
- `images missing alt`：至少一张图片缺少非空 `alt`。
- `og:image asset not accessible`：分享图不可访问或不是图片类型。
- `sitemap URL returned 404`：sitemap 包含了不可访问 URL。
- `sitemap URL has noindex`：sitemap 放入了不应收录页面。
- `external target=_blank missing rel=noopener`：新窗口外链缺少安全 rel。
- `sponsored external link missing rel=sponsored`：商业/赞助链接缺少 sponsored。
- `legacy redirect expected redirect`：历史路径没有正确 301/302 到新页面。
- `title differs between UAs`：搜索引擎 UA 与浏览器 UA 拿到的 HTML 不一致，需要排查 SSR、缓存或中间件。

## 验收口径

- 部署前：`seo:verify` 必须 `FAIL: 0`。
- 部署后：`seo:audit` 必须 `FAIL: 0`。
- 大批量内容更新后：优先跑 `seo:audit:fresh` 预热缓存，再用 `seo:indexnow --dry-run` 确认提交 URL。
- 日常巡检可跑 `seo:links` 单独检查链接技术属性。
- CI 中建议保存 `--json` 输出作为 artifact，方便追踪失败项。
