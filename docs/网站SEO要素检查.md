# 网站 SEO 要素检查

给人过的清单：基础项、进阶项，以及站点地图、规范链接、内链、结构化数据、分享信息、多语言这些地方常见的错法。因素分和「网页 / 读稿 / 后台」的分法在 [Zyppy 2026 的 101 项](zyppy-2026-101.md)。

基础版-网站SEO要素
基础要素（基础合规 + 搜索可见性保障）
可抓取 / 索引
□ 页面状态码返回正确（应为 200，避免软 404）
□ 核心页面未被 robots.txt 或 noindex 阻止
□ 不屏蔽重要资源（如 CSS/JS），确保可渲染性
□ 存在 XML Sitemap 并已提交至搜索引擎
结构与 URL
□ URL 语义清晰、无无意义参数堆叠
□ 目录结构清晰、主题归类明确
□ 页面配置 rel="canonical"，避免重复收录
SERP 展示
□ 每页独立 <title>，简洁明确含关键词
□ 每页独立 <meta name="description">，提炼页面要点
移动端适配
□ 使用 viewport，布局响应式，移动端体验正常
□ 移动页面与桌面页面信息一致（避免内容缺失）
性能与安全
□ 全站启用 HTTPS，证书有效
□ 页面加载不拖慢（Core Web Vitals 合理范围内）

进阶优化（有利于提权、用户体验等）
结构与 URL
□ 页面之间有清晰内链，合理布局站内跳转路径
□ 页面设置 <html lang> 明确语言
□ 存在 breadcrumb（如适用）
SERP 展示增强
□ 设置 Open Graph / Twitter Card 标签，用于社交平台展示
□ 添加结构化数据（Schema.org）标记产品、文章、FAQ 等
可访问性 / 图像搜索
□ 图片均设有合适的 alt 属性，描述准确
错误处理
□ 自定义 404 页面友好，提供站内跳转建议
□ 无无尽翻页/无内容垃圾页（如分页控制不当）

外链管理等（应对 UGC、链接管理类问题）
外链策略 / 用户生成内容
□ UGC 内容外链默认加 rel="ugc" 或 nofollow
□ 商业合作类链接加 nofollow 或 sponsored
□ 防范用户发帖/搜索页等生成大量无价值抓取页

进阶版—确保SEO无问题
页面结构检查
常见问题包括：
●页面缺少 title；
●页面缺少 meta description；
●页面没有 H1；
●title / description 与页面内容不匹配；
●不同语言页面混入错误语言内容；
●搜索引擎 Bot 抓到的 HTML 与浏览器看到的不一致；
●平台后台报错与线上真实 HTML 状态不同步。
这类问题会直接影响搜索引擎理解页面主题，也会影响 Bing、Google、AI 搜索对页面的基础判断。
对应检查方式：
●抓取线上真实 HTML；
●分别用普通浏览器 UA 和 BingBot / GoogleBot UA 检查；
●检查 title、description、H1、正文首屏内容是否真实存在；
●不只看后台提示，要以线上可抓取结果为准。

sitemap
常见问题包括：
●sitemap 中出现 404 URL；
●sitemap 中出现重定向 URL；
●sitemap 中出现重复 URL；
●sitemap 中残留历史时间戳 URL；
●sitemap 中包含不该收录的测试页、假路径、旧路径；
●sitemap 和 canonical 不一致；
●sitemap 已更新，但线上访问仍是旧版本。
这类问题会影响搜索引擎发现页面、判断页面终态，也容易造成重复收录和索引浪费。
对应检查方式：
●检查 sitemap 是否可访问；
●扫描 sitemap 中每个 URL 的状态码；
●检查是否存在 timestamp URL、重复 URL、旧 FAQ 路径、假工具路径；
●检查 sitemap URL 是否都是最终 canonical URL；
●部署后重新抓线上 sitemap，而不是只看本地生成结果。

Canonical 与 URL 规范化问题
常见问题包括：
●同一篇博客同时存在 .html 和无 .html 版本；
●canonical 指向错误版本；
●页面实际 URL 与 canonical 不一致；
●重定向终态和 canonical 不一致；
●历史 slug、时间戳 slug 没有被清理；
●多语言页面 canonical / hreflang 混乱。
这类问题会导致搜索引擎无法判断哪个页面才是主版本，进而出现重复收录、权重分散、错误页面被索引等问题。
对应检查方式：
●明确每类页面的终态 URL 规则；
●检查 bare URL 是否跳转到规范版本；
●检查 canonical 是否指向最终可访问页面；
●检查 sitemap 中是否只保留 canonical 版本；
●对历史 URL 做批量扫描和清理。

内链错误问题
常见问题包括：
●正文内链指向 404 页面；
●词典、模板、组件中保留旧路径；
●内链指向未上线的多语言页面；
●工具页路径写错，例如假工具路径；
●FAQ 子路径、历史路径没有被清理；
●内容源和前端组件使用不同 URL 规则。
这类问题会影响爬虫爬取效率，也会降低站内权重传递效果。对工具站、内容站、GEO 页面集群来说，内链错误还会明显影响主题聚合。
对应检查方式：
●扫描源码中的站内链接；
●扫描词典、组件、模板、公共逻辑；
●扫描已发布 HTML 中的真实链接；
●检查每个站内链接是否返回 200 或正确跳转；
●对未上线语言内容设置回落策略。

结构化数据问题
常见问题包括：
●博客缺少 BlogPosting；
●面包屑缺少 BreadcrumbList；
●author 类型不一致；
●JSON-LD 字段缺失或格式错误；
●结构化数据与页面真实内容不一致；
●历史文章没有跟上新 SEO 模板。
结构化数据不一定直接决定排名，但会影响搜索引擎和 AI 搜索对页面类型、作者、层级、主题关系的理解。
对应检查方式：
●检查页面是否输出 JSON-LD；
●检查 BlogPosting、BreadcrumbList、FAQ、HowTo 等结构是否符合页面类型；
●检查 author、datePublished、dateModified、headline、image 是否完整；
●对历史文章进行 SEO 信息回填。

OG / Twitter 分享卡片问题
常见问题包括：
●缺少 og:title；
●缺少 og:description；
●缺少 og:image；
●缺少 Twitter card 信息；
●分享图失效或 404；
●不同页面使用重复、错误或低相关性的分享信息。
这类问题主要影响社交分享、AI 浏览器摘要、搜索卡片展示，以及外部平台识别页面内容的质量。
对应检查方式：
●检查 OG / Twitter meta 是否完整；
●检查分享图是否可访问；
●检查分享标题和描述是否与页面主题一致；
●对历史博客做批量回填。

Robots / llms / 抓取入口问题
常见问题包括：
●robots.txt 不可访问；
●robots 错误屏蔽重要页面；
●sitemap 地址没有写入 robots；
●llms.txt 不可访问；
●AI crawler 入口文件缺失；
●搜索引擎和 AI 爬虫看到的内容不一致。
这类问题会影响 Google、Bing 和 AI 搜索系统发现站点内容，尤其是 GEO 场景下，llms.txt、清晰 sitemap、稳定 HTML 输出会变得更重要。
对应检查方式：
●检查 robots 是否 200；
●检查 robots 中 sitemap 地址是否正确；
●检查 llms.txt 是否 200；
●用 Bot UA 抓取重点页面；
●避免纯 CSR 页面导致 AI crawler 抓不到核心内容。

多语言 SEO 问题
常见问题包括：
●hreflang 缺失；
●hreflang 指向不存在页面；
●多语言页面之间互相引用不完整；
●hk / jp 等语言入口指向未上线文章；
●页面语言和导航语言混乱；
●未上线语言内容没有 fallback 策略。
这类问题会影响不同地区、不同语言用户的搜索体验，也可能导致搜索引擎错误理解页面语言和目标区域。
对应检查方式：
●检查 hreflang 是否完整；
●检查 hreflang 目标 URL 是否可访问；
●检查页面语言、导航语言、canonical 是否一致；
●未上线语言内容优先回落到英文终态页面；
●多语言词典变更前做链接校验。

静态资源与中间件问题
常见问题包括：
●静态资源已经部署，但公网 404；
●middleware 把静态路径错误改写到语言路径；
●demo 文件、PDF 示例、图片资源被 rewrite 规则误伤；
●图片、PDF、OG 图在本地可访问，线上不可访问。
这类问题容易被误判为“资源没部署”，但实际可能是中间件、Nginx 或路由规则的问题。
对应检查方式：
●检查资源是否在容器或服务器目录中真实存在；
●检查公网 URL 是否返回 200；
●检查 middleware 是否排除了静态资源目录；
●检查 Nginx 是否正确转发静态资源路径。
